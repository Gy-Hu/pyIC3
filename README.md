## Usage

All entry points go through `run.py`. For benchmarks, see `experiment/blocksys_benchmarks/` (organized as `safety/<name>/{original,data,auxiliary}` and `liveness/<name>/{original,data}`).

### Vanilla IC3

```bash
# Legacy positional form
python run.py xxx.aag

# Equivalent flag form
python run.py --aag xxx.aag --no-llm
```

### LLM-Guided IC3

Requires: `pip install requests`, and a `.env` file with LLM API credentials (see `.env.example`).

Also requires: `yosys`, `yosys-abc`, `aigtoaig`, `aigmove` for Verilog-to-AIGER conversion (see `experiment/convert_all.sh`).

```bash
# From Verilog source (auto-converts via Yosys, generates LLM hints, runs IC3):
python run.py -v design.v --top module_name

# From pre-converted AIGER + symbol map:
python run.py --aag model.aag --map model.map -v design.v

# Compare vanilla vs LLM-guided side by side:
python run.py --aag model.aag --map model.map -v design.v --compare

# Load pre-verified hints from JSON (skip LLM call):
python run.py --aag model.aag --map model.map --load-hints model_hints.json

# Run all BlockSys benchmarks (uses experiment/blocksys_benchmarks/):
python run.py --batch
```

The `--map` file is generated by the Yosys `aigmap` pipeline and maps AIGER latch indices to Verilog variable names. This mapping allows the LLM to generate predicates using RTL-level names (e.g., `held_0`, `ep_0`) that are automatically encoded as Z3 expressions over the correct bit-level latch variables.

Older / experimental scripts (`run_silent.py`, `test_compare.py`, `test_llm_ic3_loop.py`, the original 43-line `run.py` saved as `run_legacy.py`) live under `deprecated/`.

## Techniques I used

### Algorithmic
- one-context-for-all-frame solver (good to re-use the solving context) [[arbrad 15]](https://github.com/arbrad/IC3ref/issues/4)
- on-demand logic cone extraction (partially implemented) [[arbrad 15]](https://github.com/arbrad/IC3ref/issues/4)
- ctgDown / Down in MIC [[Z Hassan 13]](https://www.cs.utexas.edu/users/hunt/FMCAD/FMCAD13/papers/85-Better-Generalization-IC3.pdf)
- ternary simulation - for predecessor aggresive generalization (not suitable for python implementation) [[N Een 11]](http://een.se/niklas/eff_impl_pdr.pdf)
- infinite mic attempt (suggestion from arbrad) [[arbrad 15]](https://github.com/arbrad/IC3ref/pull/6)
- literals ordering according to their appearance in the trace (frequency), both in predecessor generalization (ternary sim) and inductive generalization (mic) [[arbrad 15]](https://github.com/arbrad/IC3ref/blob/master/IC3.cpp)
- IC3 with innards for better generalization [**WIP**] [[Rohit Dureja 21]](https://ieeexplore.ieee.org/document/9617709)

### Others
- robust sanity checker
- rich console output for logging and monitoring
- cube and frame management system (add, join, push, etc.)
- unsat core extraction for inductive generalization and predecessor generalization
